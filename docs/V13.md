# V13 - Public-Led Family Refinement

V13 is the first version to use the public score as bounded feedback during a session. Earlier versions generated every prediction before seeing feedback and then used the leaderboard only to choose finalists. V13 keeps the train-only p01 hedge but uses the three public-leading Stage 1 files to construct a small Stage 2 blend frontier.

## Motivation

V3 through V7 and V8.1 through V12 all returned the same official 0.822 AUC. Fixed additions such as refits, neural models, equation features, and count views did not transfer visibly to the hidden pair. This suggests that the hidden datasets may require different model families and that a fixed router cannot identify the family reliably from train CV alone.

## Architecture

### Stage 1

`automl.py` fits the established mixed-type portfolio and emits at most thirteen files.

- p01 is the strongest leakage-safe train-CV candidate.
- The first ten files cover direct CatBoost, LightGBM, ExtraTrees, Random Forest, histogram boosting, linear/additive, kernel, XGBoost, and routed representations when available.
- Up to three safety files append shallow CatBoost, ordered CatBoost, and a specialist-excluding historical blend without evicting the first ten.

All Stage 1 predictions are created without test labels or public feedback.

### Stage 2

After Stage 1 is submitted, the agent passes the top three public-scoring filenames and p01 to `refine.py`. The script creates eight rank blends:

- three leader/runner-up weights;
- three leader/third-place weights;
- one leader/runner-up/third mixture;
- one leader/runner-up/p01 mixture.

The public score chooses only the input files. The refinement script never receives public labels or score values.

### Final selection

The highest-public Stage 1 file is the initial public-led finalist. The best refined file replaces it only when its public AUC is at least 0.0001 higher. The other finalist is p01. If p01 is already the public-led finalist, the highest-public other modeled file occupies the second slot.

The initial `sample_submission.csv` call guarantees a valid fallback before any skill or modeling call.

## Budget

| Component | Maximum |
|---|---:|
| Fallback submissions | 1 |
| Stage 1 submissions | 13 |
| Stage 2 submissions | 8 |
| Total prediction submissions | 22 of 30 |
| Final selections | 2 |

Stage 2 only reads and blends saved CSVs, so it adds seconds rather than minutes. The training runtime remains dominated by the inherited Stage 1 portfolio.

## Replay evidence

The diagnostic two-stage replay produced useful gains on multiple solved generators:

| Dataset | Selected-private delta vs older V8 snapshot |
|---|---:|
| Train 09 | +0.001981 |
| Train 10 | +0.001420 |
| Train 11 | +0.002486 |
| Train 14 | +0.002218 |
| Train 05 | +0.000636 |

The mean replay was approximately neutral (`-0.00004`) because Train 13 differed sharply from the older saved V8 model state. Appending the missing shallow/ordered CatBoost files and lowering the replacement gate improved V13's Train 13 result from 0.649242 to 0.650725, but the old snapshot remained materially higher.

The planned +0.002 mean transfer gate was not cleared. The official V13 score was **0.822 AUC**, so within-session public blend refinement did not break the repeated plateau.
