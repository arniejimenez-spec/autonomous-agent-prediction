# V2.1: fail-safe harness correction

## Observed failure

The v2 competition session ended with: `submit_predictions was never called`.

## Root cause

Google ADK's `run_skill_script` implementation materializes bundled scripts in a temporary directory and changes the process working directory before running them. The competition CSV files live in the persistent Docker directory `/work`. V2 expected the CSV files in its current directory, so a direct skill invocation failed before producing candidates. The supplied competition skill documentation stated that skill scripts run beside the CSV files, which does not match the installed ADK implementation.

## Corrections

1. The modeling script locates and enters `/work` before reading or writing files.
2. The agent's first tool call submits `sample_submission.csv`, guaranteeing at least one valid prediction submission even if all modeling fails.
3. The prompt specifies the exact `load_skill` and `run_skill_script` tool names, skill name, script path, and recovery arguments.
4. Recovery never permits a plaintext exit before a valid submission.
5. The orchestration model is upgraded from `gemini-3.1-flash-lite` to `gemini-3.5-flash` for stronger tool adherence while remaining inside the $2 budget.

The deterministic ML portfolio is unchanged from v2. A smoke test reproduces v2's task-13 AUC of 0.648783.
