# V8: DGP-Probing Portfolio

V8 changes both candidate generation and final portfolio selection. It uses train-only out-of-fold evidence to identify smooth-additive, local-kernel, categorical, and interaction/threshold dataset profiles, exposes a wider candidate frontier, and pairs the public leader with the highest-CV hedge.

## Why the first meta-router was rejected

A ridge candidate ranker was trained on dataset fingerprints and candidate descriptors. Its outer validation unit was an entire mini-competition: for each task, all candidates from that task were held out while the ranker trained on the other fifteen. Ridge regularization was selected by a second group-held-out loop inside each outer training fold.

On the v7 frontier:

- learned meta hedge: 0.805550 selected-private AUC;
- highest-CV hedge: 0.805614;
- v7 policy: 0.805604.

The learned selector did not beat the simpler train-CV rule, so its coefficients are not bundled into the agent. `scripts/analyze_meta_router.py` preserves the rejected experiment as an auditable result rather than turning a small-sample meta-fit into runtime complexity.

## DGP probes

V8 adds three deliberately different model families:

- spline logistic regression for smooth additive effects;
- histogram gradient boosting for threshold-heavy generators;
- an RBF support-vector classifier on small, low-dimensional datasets for local smooth boundaries.

All probe decisions use training data only. A probe-specific blend is created only when its leakage-safe OOF AUC is within a fixed tolerance of the strongest base model. Historical v5, v6, and v7 families remain available as direct candidates.

## Two-slot portfolio

V8 uses more of the 30-submission budget:

1. submit the sample file first as a guaranteed fallback;
2. submit every distinct modeled candidate, capped at 28;
3. select the highest-public modeled candidate;
4. use the highest-CV candidate as the second slot, or the second-highest public candidate when the CV hedge already leads.

The public score never changes prediction values or activates a new model.

## Evidence

The 16-task fast replay under the exact v8 selection rule reaches:

- v7 selected-private mean: 0.805604;
- v8 selected-private mean: 0.805725;
- mean change: +0.000121;
- improved tasks: five;
- regressions: zero.

The largest gain is `train_06` at +0.000856. Other gains appear on `train_01`, `train_04`, `train_08`, and `train_14`.

Normal four-fold confirmations completed in approximately 9.5 minutes on `train_01` and 6.8 minutes on `train_06`, well inside the 60-minute per-session limit.

These solved-task results are development evidence, not an estimate of the hidden leaderboard score. V7 also improved locally without moving beyond 0.822, so v8 remains officially unscored until Kaggle evaluates it.

## Reproduction

```powershell
.\.venv\Scripts\python.exe scripts/replay_v8_policy.py `
  submissions/09_meta_routed_automl_v8/meta_results_all.json `
  --baseline-results submissions/08_fingerprint_routed_automl_v7/meta_results_all.json `
  --baseline-hedges submissions/08_fingerprint_routed_automl_v7/policy_hedges.json
```

The learned-router audit can be rerun with:

```powershell
.\.venv\Scripts\python.exe scripts/analyze_meta_router.py `
  --results submissions/09_meta_routed_automl_v8/meta_results_all.json `
  --output submissions/09_meta_routed_automl_v8/meta_router_exploratory.json
```
